The pen and the bushel

A drawing tablet arrives tomorrow morning. It is not an accessory — it is the input device for the one judgement this project has proven, three separate times, cannot be computed.

The answer

Yes — and it lands exactly on the blocker

This project's store already contains the finding that makes the tablet load-bearing rather than convenient. From no-whole-tree-to-segment:

A whole-tree mask can only be AUTHORED — a lasso is a human judgement about which marks are one tree, and that judgement is not in the pixels.

Wang Meng draws a tree as separate marks over bare silk — leaf sprays, twigs, a trunk — with no enclosing contour and no filled silhouette. Every automatic method therefore answers a different question than the one asked. That conclusion has now been reached from four directions:

SAM 1 point promptsreturns individual leaf sprays — real objects, never the tree

Against that, your own estimate of the manual path:

"my eyes can easily define these bushels… I could tell you exactly what trees and where the pivot points are, what parts of the bushel. That would fix everything and it would take five minutes."

So the tablet is not a productivity upgrade — it closes an open architectural question. Phase 0 of the plan is "the cut", and its own work list already ends with "let a click define the bushel and skip the automatic cut entirely." The hardware to do that arrives tomorrow.

What the device changes

A Deco is not an iPad, and that is good news

The existing research doc (docs/2026-08-25-authoring-surface-research.md) left one question open: "What pen surface exists today?" It had assumed the answer would be an iPad, and designed around it — a web page served off this Mac, opened in iPad Safari, Apple Pencil reaching the page through Pointer Events.

An XP-Pen Deco is a different class of device: a screenless pen tablet that drives the Mac's cursor directly. Every consequence of that is in our favour.

iPad + Pencil (assumed)XP-Pen Deco (actual)
Reaches Blender?No — needs a web layer, or sidecarYes, natively. It is a system pointer
Software forkPage must run in Safari and on MacNone. One surface, on the Mac
Input plumbingPointer Events, coarse pointermove sampling on SafariDriver-level. Nothing to write
Hand–eyeDirect (draw on the picture)Indirect — hand on pad, eyes on screen
Screen real estateSecond screen gainedNone gained — main display only

The one real risk, and why it is small. XP-Pen + Blender + macOS has a documented history of pressure-sensitivity failures — three separate Blender bug reports (T77306, #58030, T62185). One report notes pressure works in Grease Pencil even where it fails in sculpt mode.

It barely matters here. We need position and click, not pressure. Circling a bushel and dropping a pivot are pointer gestures; nothing in this workflow varies line weight by how hard you press. If pressure never works, the workflow is unaffected.

The trade that is real is indirect hand–eye. Drawing a portrait that way takes practice. Circling a region and tapping a pivot does not — it is closer to using a trackpad than to drawing, and it is precise enough at the scale we mark at.

Corrections

Two findings in the existing research doc are now wrong

1 · SAM 3 is not gated after all

Finding #3 said the weights are "gated — Meta must approve the account", and treated that as a blocker needing a real download attempt. That is true of facebook/sam3. It is not true of the MLX community port: mlx-community/sam3-image is Apache 2.0 and freely downloadable, 3.4 GB, built for M-series. There is no approval to wait on and no gate to negotiate.

But note what it accepts. The MLX port documents text prompts and box prompts — it does not document point or exemplar prompts. For us this is close to irrelevant and arguably better: a box drawn with a pen is the natural gesture, and open-vocabulary text ("tree") is precisely what this painting defeats. Human box, machine refine.

2 · The authoring path is Blender, not Procreate

The plan's open question — "whether an iPad exists, which decides whether the Procreate → Frame By Plane authoring path is real or theoretical" — is now answered: no iPad, so that path is theoretical and should be dropped. The Deco makes the Blender viewport itself the authoring surface, which is a shorter route and satisfies the standing directive at the same time.

The trap

Annotations and Grease Pencil are not the same thing

The obvious design — "he scribbles with the Annotate tool, I read the strokes in Python" — hits a known regression. Blender issue #147732: creating Annotation strokes and points via the Python API is unavailable in Blender 4.3 and up. This Blender is 5.2.1.

The fix is precise and costs nothing if known in advance: use a Grease Pencil object, not the Annotate tool. Grease Pencil stroke data is fully reachable — GreasePencilDrawing.attributes is the documented performance API for point coordinates, with drawing.strokes[n] as the compatibility path.

They look identical while you are drawing. Only one of them can be read back. This is the kind of detail that quietly eats a session, which is why it is in this report rather than discovered on Wednesday.

The real prize

Your marks stop being descriptions and start being data

You framed this as "another surface to communicate through", and that is the part worth designing carefully — more than the cutting itself.

Today, pointing at something costs you a paragraph and costs me a guess. "The big tree on the left, above the bridge, not the pine — the one with the reddish tips" becomes my interpretation of your sentence, and the failure is invisible until a render comes back wrong. That round trip has been the dominant cost in this project: an-absence-is-invisible-in-the-output exists because eleven days of renders were all missing something nobody could see.

A drawn mark has no interpretation step. It is a polygon in master coordinates. The ambiguity does not get resolved — it never exists.

The loop, once it is wired

01
You circle

A rough loop around one bushel on the painting, in the Blender viewport. Seconds, not precision.

02
SAM tightens

Your loop becomes a box prompt; SAM 3 snaps it to the actual ink inside it.

03
You tap the hinge

One dot where the spray joins the branch. That is the pivot — the thing no algorithm can find.

04
It becomes a card

Written where the pipeline already reads. hinge-foliage stops guessing and starts obeying.

And the same channel runs backwards, which is the half that makes it feel good: when a render is wrong, you mark on the frame what is wrong. Not a description of the tree that wobbled — the tree that wobbled, circled. That is a shared coordinate system, and this project has never had one.

Where the joy actually comes from is latency. SAM 3's image encoder runs once per tile; each prompt then decodes in milliseconds. Done right this feels like the iPhone lift-subject gesture — tap, it pops. Done wrong it is a progress bar per click, and you will stop using it by the third tree. Interactive-speed decode is the acceptance criterion, not a nice-to-have.

Tomorrow

The first hour, in order

Deliberately small and verifiable, because every step below can fail for boring reasons and each one should fail loudly and early rather than at the end.

  1. Driver first. XP-Pen's own macOS driver is mandatory — without it, pressure, tilt, express keys and screen mapping are all unreliable. macOS will also demand Accessibility and Input Monitoring permissions; expect a reboot.
  2. Prove the pointer in Blender before anything else. Draw one Grease Pencil stroke in the viewport. If the cursor tracks and a stroke appears, the hard dependency is satisfied — pressure can stay broken.
  3. Read that stroke back in Python. One script, printing point coordinates from drawing.attributes. This is the whole bridge; everything else is built on it.
  4. Map one stroke to master coordinates on a real zone plate, and open the overlay so you can see your own loop drawn back onto the painting. That is the moment the channel exists.
  5. Only then pull SAM 3 MLX (3.4 GB) and put the refine step behind the loop.

Steps 1–4 need no downloads, no model, and no network. They are worth doing the morning it arrives, before any decision about SAM.
