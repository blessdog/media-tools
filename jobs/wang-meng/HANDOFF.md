## The cleanup, in order

Measured 2026-08-25: **32GB total, 25GB of it in `journey/`**, 57,879 PNGs
(7.2GB) and 504 MP4s (1.7GB). Nothing is untracked, so nothing is at risk of
being lost — this is bloat, not loss.

```

jobs/wang-meng/film/reap-frames.sh --go     # only after reading the dry run
```

**Done when:** repo under 10GB, and `git status` still clean.

### 2. Audit `journey/` — the 25GB

Each zone carries `layers-cut`, `layers-heal`, `layers-pinned`, `layers-sealed`,
`layers-filled`, `relief/`, `living-work/`, `living-masks/`. Only some are
inputs to the current pipeline; the rest are stages of a build that already
completed.

**The rule that decides it:** a stage whose output is fully contained in a later
stage is scaffolding. `layers-filled` is what `blender-multiplane.py` reads.
Establish for each earlier stage whether anything still reads it — `grep -rn` the
tools, do not guess — then reap or keep with a written reason.

**Done when:** every `layers-*` directory is either read by a live tool or
recorded in `knowledge/` as scaffolding, with the grep that proved it.

### 3. The other ten jobs

`jobs/` holds eleven jobs; ten are old inkwash probes (`dog-inkwash`,
`knife-inkwash`, `yakub-inkwash`, `ryan-ink`, `ryan-portrait`, `krea-probe`,
`stitch-test`, `sheen-inkwash`, `inkwash-flf2v`, `krea`). Several carry real
verdicts — `jobs/krea/VERDICTS.md` is 192 lines of them.

**Do not delete any of it.** For each: is its finding already a claim in
`knowledge/`? If yes, the job dir is evidence and can be reaped down to its
evidence files. If no, **write the claim first**, then reap.

**Done when:** every job either has a live claim pointing at it, or a one-line
entry in `knowledge/` saying it was a probe with no surviving finding.
